# AGENTS.md — Engineering rules

Conventions for AI coding agents here: how code is written, tested, documented,
committed. **Conventions only.**

What this project *is* and why lives in [docs/](./docs) — `docs/design/` is the
authority on contracts and behaviour, `docs/decisions/` holds the ADRs. On a
project-specific fact, `docs/` wins over this file.

[ASSESSMENT.md](./ASSESSMENT.md) governs [LIFECYCLE.md](./LIFECYCLE.md); a new
step of work `MUST` be recorded there when it begins.

`MUST`/`MUST NOT` mandatory · `SHOULD`/`SHOULD NOT` recommended, deviation needs
justification (RFC 2119). Code, comments, identifiers, commits and docs `MUST`
be English.

---

## 1. Autonomy

| Level | Actions |
|---|---|
| **Always proceed** | Code and tests, refactoring within a file, fixing failures, naming |
| **Ask first** | Schema changes, adding or upgrading dependencies, build and CI config, a new layer, altering a public contract, deleting a test |
| **Never** | Committing secrets or `.env`, disabling lint or type checks, adding a dependency to avoid ten lines, weakening a test or an enforced boundary to let something through |

- Changing a test is legitimate only when the expected behaviour changed — say
  so in the commit.
- A claim about a file `MUST` be checked against the file on disk before acting
  on it. Remembered context goes stale; a confident report of a contradiction
  that does not exist is worse than no report.
- **When a problem would have been prevented by a rule that is not here yet,
  proposing that rule is part of fixing the problem.** State the incident, the
  rule, and where it belongs. Do not edit this file unilaterally — propose.
  Rules earn their place from incidents, not from taste.
- A rule `MUST` be general enough to survive a change of framework or database.
  Anything true only of this stack is a fact and belongs in `docs/`.

## 2. Architecture

**Layout.** Feature-first: `src/` is a map of domains, not of layers. Every
domain module `MUST` contain exactly `controller/`, `service/`, `repository/`.
Cross-cutting code sits outside them (`common/`, `config/`, `database/`).

Directories `MUST NOT` group by language construct or framework mechanism
(`types/`, `interfaces/`, `filters/`). A type lives with the layer that owns it;
one shared by two layers of a module lives at that module's root. Ambient
declarations (`*.d.ts`) are the only exception.

**Boundaries.**

- Boundaries `MUST` be enforced by tooling, not discipline
  (`import-x/no-restricted-paths`, `no-restricted-imports`).
- When an enforced boundary blocks the code, **the code moves — the boundary
  does not**. Widening an exemption requires an ADR.
- Transport `MUST NOT` hold business rules; business code `MUST NOT` know the
  transport — no request/response objects, no status codes.
- Persistence models `MUST NOT` be serialised outward. Responses are explicit
  types listing their fields, so a new column cannot leak into the API.
- The ORM `MUST NOT` be importable outside the data-access layer.
- Repository signatures `MUST` be in domain terms: `applyStockDelta(token,
  delta, tx)` is a boundary, `update(where, values)` is the ORM renamed.

**Dependencies.**

- Every imported module `MUST` be a declared direct dependency — never a
  transitive one.
- Side-effectful global imports (polyfills) `MUST` sit at the composition root,
  never in a domain file.
- Dependencies `MUST` be injected, never constructed inline.
- Depend on a concrete class until a second implementation exists; a port with
  one implementer buys nothing that method shape and a lint rule do not.
- A new abstraction `MUST` be explainable in one sentence.

## 3. TypeScript

- `strict` on, never relaxed per file.
- `any` `MUST NOT` be used — `unknown`, then narrow.
- The non-null assertion operator (`value!.field`) `MUST NOT` be used. The
  definite-assignment assertion on a validated DTO field (`readonly x!: string`)
  is allowed: the validator populates it.
- Exported functions `MUST` declare their return type.
- Never-reassigned fields `MUST` be `readonly`.
- Types `SHOULD` make invalid states unrepresentable.

## 4. Naming

| Subject | Convention |
|---|---|
| Files | `kebab-case` |
| Types, classes | `PascalCase` |
| Functions, variables | `camelCase` |
| Constants | `UPPER_SNAKE_CASE` |
| Tables / columns | lowercase plural / `camelCase` |

Booleans read as predicates (`isActive`, `hasStock`). No abbreviations, no
type-encoding. One concept, one name, across every layer.

## 5. Functions and readability

- One thing per function, named for it, no hidden side effects.
- Parameters `MUST NOT` be mutated — return new values.
- Four parameters at most; beyond that, an options object.
- Early return over nesting; a complex ternary becomes `if`/`else`.
- Meaningful literals `MUST` be named constants.
- Dead code `MUST` be removed — git is the safety net.

## 6. Error handling

- Typed classes extending a shared base — no bare `Error`, strings or untyped
  objects.
- Domain-to-transport translation happens **once**, at the outer boundary, and
  covers framework errors too, or the API answers in two shapes. Unmapped
  errors surface as a generic `500`.
- Responses `MUST NOT` expose stack traces, query text or schema details.
- Driver and constraint violations `MUST` be translated into domain errors by
  the layer that knows the driver.
- An empty `catch` `MUST NOT` exist.

## 7. Async and data

- Every promise `MUST` be awaited or returned; `async` only where something is
  awaited.
- A single statement is already atomic. A transaction `MUST` be opened when, and
  only when, several statements must succeed or fail together.
- Transactions `MUST` be passed explicitly, so a signature states what
  participates.
- Mutations of a contended value `MUST` be atomic — one conditional `UPDATE`,
  never read-modify-write.
- A retryable non-idempotent operation `MUST` be protected by an idempotency
  key, whose record `MUST` share the transaction of the effect it protects.
- Constraints (uniqueness, nullability, ranges) `MUST` be enforced at database
  level, not only in validation. A constraint is not implemented until something
  has been **observed failing against it**: a declaration the engine silently
  ignores looks identical to one that works.
- Every blocking operation `MUST` carry an explicit timeout — an inherited
  default is not a decision.
- Whatever opens a resource `MUST` expose how to close it, and the opener closes
  it. A test run that does not exit on its own has a defect, not noise.
- Input `MUST NOT` be coerced into validity. Trimming is normalisation;
  rounding to fit is a decision taken for the client, and `MUST` be a rejection.
- Queries `MUST` be parameterised. Money is fixed-point decimal, never float,
  and crosses the wire as a string.

## 8. Security

- Secrets come from the environment only; `.env` uncommitted, `.env.example`
  committed.
- Configuration `MUST` be validated at startup and fail fast.
- External input `MUST` be validated at the boundary, rejecting unknown fields.
- Secrets, credentials and PII `MUST NOT` be logged.
- Secrets `MUST` be excluded at **every** artifact boundary — version control,
  image build context, anything published. Each has its own ignore file and each
  is a separate way to leak.

## 9. Testing and verification

- Tests live in `test/unit/` (mirroring `src/`) and `test/e2e/`, so `src/` holds
  production code only.
- A unit test isolates its unit: I/O collaborators substituted, pure ones real.
- End-to-end tests run real migrations against a real database. `sync()`
  `MUST NOT` be used, in application code or tests.
- Failure and edge cases `MUST` be covered: boundaries, constraint violations,
  absent resources, invalid input, concurrent access.
- One behaviour per test; the name states it.
- Tests `MUST` be deterministic, order-independent, and pass from a clean
  checkout.
- Verification `MUST` interrogate the running system, never re-read the code
  that produced it — ask the database for its schema, run the built artifact,
  send the request. Reading a definition back only proves it was written.
- A build is unfinished until the artifact it produced has been **executed**.
- Every command — install, lint, type-check, test, migrate, run — `MUST` run
  inside a container; the host runtime is not the one that ships. A `Makefile`
  target `SHOULD` wrap each.

## 10. Comments and documentation

- Comments explain *why*. A line that looks wrong and is correct carries an
  inline `// why`.
- No commented-out code, no `TODO`/`FIXME` on the main branch.
- JSDoc covers the public surface only and `MUST NOT` restate types.
- The README covers prerequisites, setup, run, test, and one request/response
  example per endpoint.
- Decisions are recorded as ADRs in `docs/decisions/`.
- A document contradicting the code is a **defect**, corrected in the change
  that made it untrue. A stale claim costs more than a missing one: it is
  believed.

## 11. Git

- Conventional Commits: `type(scope): subject`, imperative, ≤72 chars, no
  trailing period. Body optional, bullets only.
- Branches `type/short-description`, kebab-case.
- One logical change per commit, with lint, build and tests green.
- Lockfile committed; secrets, build output and editor config not.
- Trailers `MUST NOT` credit tooling — AI use goes in `LIFECYCLE.md`.

## 12. Principles (tiebreakers)

**KISS** · **YAGNI** · **DRY** (knowledge, not shape) · **SOLID** ·
**Boy Scout rule**, scoped to the area worked on.

Above all **explainability**: every line justifiable in one sentence.
Over-building counts against.
